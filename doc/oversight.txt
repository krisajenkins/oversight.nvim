1. INTRODUCTION                                       *oversight-introduction*

oversight is a Neovim plugin for reviewing code changes, particularly those
generated by AI tools. It provides a side-by-side diff view with the ability
to add comments, mark files as reviewed, and export review summaries.

The diff itself is Neovim's own: the file at the base revision goes in one
window, the working copy in the other, and |:diffthis| does the rest. So
|]c|, |[c|, 'diffopt' and your syntax highlighting all behave as they do in
any other diff.

Supports both Git and Jujutsu (jj) version control systems with automatic
detection.

Key features:
- Side-by-side diff view of uncommitted changes, drawn by Neovim's own diff
- Line-level and file-level comments
- Mark files as reviewed (folds reviewed files)
- Export comments to clipboard for pasting into PRs/issues
- Comments and review status reset when the underlying diff changes
- Multi-VCS support (Git and Jujutsu)
- Open views refresh themselves when the repository changes on disk

Review sessions are held in memory for the lifetime of the Neovim session and
are not written to disk. Export your comments before quitting.

==============================================================================
2. REQUIREMENTS                                       *oversight-requirements*

- Neovim >= 0.9.0
- git or jj (Jujutsu) - at least one must be in PATH
- plenary.nvim (https://github.com/nvim-lua/plenary.nvim)

Run `:checkhealth oversight` to verify your setup.

                                                             *oversight-vcs*
Version Control Support~

oversight automatically detects your version control system by walking up
the directory tree:

1. Jujutsu (jj) - detected by `.jj/` directory (checked first)
2. Git - detected by `.git/` directory or file

Jujutsu repositories are checked first because they also contain a `.git/`
directory (jj uses git as its storage backend).

The review experience is identical regardless of which VCS you use.

3. INSTALLATION                                       *oversight-installation*

Using lazy.nvim: >lua
    {
        "krisajenkins/oversight.nvim",
        dependencies = { "nvim-lua/plenary.nvim" },
        config = function()
            require("oversight").setup()
        end,
    }
<

Using packer.nvim: >lua
    use {
        "krisajenkins/oversight.nvim",
        requires = { "nvim-lua/plenary.nvim" },
        config = function()
            require("oversight").setup()
        end,
    }
<

    require("oversight").setup()
<

This registers the `:Oversight` command for opening the review interface.

==============================================================================
5. COMMANDS                                              *oversight-commands*

                                                                  *:Oversight*
:Oversight [dir]        Open the code review interface for the specified
                        directory. If no directory is given, uses the current
                        working directory.

                        The interface opens in a new tab with three windows:
                        - Left: File list with review status
                        - Middle: The file at the base revision
                        - Right: The working copy

                        The two right-hand windows are in diff mode, so they
                        scroll together and Neovim aligns them with filler
                        lines.

6. KEYBINDINGS                                        *oversight-keybindings*

                                            *oversight-keybindings-navigation*
Navigation~

    j / k               Scroll up/down
    Down / Up           Scroll up/down
    Ctrl-d / Ctrl-u     Half page down/up
    Ctrl-f / Ctrl-b     Full page down/up (diff/file view only)
    { / }               Previous/next file
    [ / ]               Previous/next hunk, wrapping (diff view only)
    g / G               First/last file (file list/tree only)
    l / h               Expand/collapse directory (file tree only)
    Right / Left        Expand/collapse directory (file tree only)
    Tab                 Switch between panels (browse mode only)
    Ctrl-w h / l        Move between windows

Review mode binds no panel-switching key. Its three windows are ordinary
windows in an ordinary layout, so |CTRL-W_h| and |CTRL-W_l| already move
between them.

The two diff panes are scrollbound, so the scrolling keys move both at once.
Neither is mapped by the plugin: they are Neovim's own.

                                            *oversight-keybindings-file-list*
File List~

    Enter               Select file (show diff in right panel)
    o                   Open file in new tab for editing
    r                   Toggle file as reviewed

                                                *oversight-keybindings-review*
Diff View~

Both sides of the diff carry the same keys.

    r                   Toggle file reviewed
    c                   Comment on this line, or edit the one already there
    C                   Add file-level comment
    dd                  Delete this line's comment
    o / Enter           Open the working copy in a new tab, at this line

A comment is drawn as virtual lines under the line it is about, on whichever
side you wrote it. The same block, blank, is placed on the other side: Neovim's
diff does not count virtual lines when it aligns the two windows, so without
the mirror the panes would drift apart below the first comment.

Commenting on the base pane records the line number as it was at the base
revision; the export marks those as `Line ~N (deleted)`.

                                               *oversight-keybindings-comment*
Comment Dialog~

    Ctrl-s / Ctrl-Enter Submit comment
    Esc                 Save comment (or discard if empty)
    q                   Discard comment
    Ctrl-t / Tab        Cycle comment type
    1 / 2 / 3           Set type: suggestion/issue/question

                                                *oversight-keybindings-export*
Export & Clear~

    y                   Yank (copy) all comments to clipboard
    X                   Clear all comments (with confirmation)

                                                 *oversight-keybindings-other*
Other~

    R                   Refresh status (re-fetch changes from VCS)
    ?                   Show help overlay
    q                   Quit review (closes tab)

7. CONFIGURATION                                    *oversight-configuration*

`setup()` registers the |:Oversight| command and sets up the plugin's highlight
groups. It takes a single option: >lua
    require("oversight").setup({
        watch = true,
    })
<
                                                      *oversight-setup-watch*
watch ~
                        Type: boolean, Default: `true`

                        Auto-refresh open views when the repository changes on
                        disk. See |oversight-watch| below.

Colours are controlled by overriding the plugin's `Oversight*` highlight
groups (see `lua/oversight/highlights.lua` for the full list) rather than
through setup options. The diff itself is painted by Neovim's own |hl-DiffAdd|,
|hl-DiffChange|, |hl-DiffDelete| and |hl-DiffText|.

                                                    *oversight-diffopt*
'diffopt'~

Review mode renders with Neovim's diff, so 'diffopt' is what draws it. It is a
global option belonging to you, and oversight never writes to it. A good
setting: >lua
    vim.opt.diffopt = "internal,filler,closeoff,linematch:60"
<
`internal` selects Neovim's built-in diff library rather than an external
`diff(1)`, and `linematch` lines changed lines up within a hunk, which makes a
small edit much easier to read. `:checkhealth oversight` warns if `internal` is
missing.

8. AUTO-REFRESH                                            *oversight-watch*

oversight is meant for reviewing changes as they are being made, so open views
keep themselves up to date rather than waiting for you to press `R`.

There is no cheap filesystem answer to "did anything in this tree change", so
two signals are combined:

1. Stat-based polling of the VCS metadata (`.git/index`,
   `.jj/repo/op_heads/heads`, covering commits, staging and jj operations) and
   of the files that currently have changes. Fast - about 150ms - and free, but
   blind to any file it is not already watching.
2. A query to git or jj every two seconds, comparing the change list. Slower,
   but the only thing that notices a clean file becoming a changed one.

Events are collapsed over 150ms, so one save produces one refresh. A
watcher-driven refresh is silent; a manual `R` still reports what it did.

The one thing neither signal notices is a brand-new *untracked* file, because
`git diff HEAD` does not report untracked files at all - press `R` for that.

Reading a repository is not free of side effects in jj: `jj status` snapshots
the working copy, which writes a new operation. Events raised during a refresh
are therefore ignored, so a refresh cannot trigger itself.

Set `watch = false` in |oversight-setup| to turn all of this off.

==============================================================================
9. HEALTH CHECK                                          *oversight-health*

Run `:checkhealth oversight` to verify your installation:

- Checks Neovim version (>= 0.9.0 required)
- Reports the version and path of git and/or jj, or that neither was found
- Reports which VCS the current directory uses (Git or Jujutsu)
- Warns if 'diffopt' has no `internal` (see |oversight-diffopt|)
- Verifies plenary.nvim is available

No minimum version is asserted for git or jj: oversight uses only long-stable
git subcommands, and a jj floor would be guesswork. The discovered versions are
reported so they are to hand when diagnosing a problem.
